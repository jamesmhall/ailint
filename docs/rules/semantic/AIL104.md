# AIL104 `negative-constraint-overload`

LLMs often perform better with affirmative instructions rather than exhaustive lists of prohibitions. If a guidance file is overwhelmingly composed of negative constraints (e.g., "do not", "never", "avoid"), the agent may struggle to follow the guidelines effectively.

This rule flags documents where the majority of list items are framed as negative constraints.

## Why this is bad
Agents guided by long lists of "don'ts" are more prone to context drift and hallucination. They lack clear instruction on the desired behavior.

## How to fix it
Refactor the constraints to affirmatively describe what the agent *should* do.

```markdown
<!-- Bad -->
- Never use var.
- Do not use class components.
- Avoid any-types in TypeScript.

<!-- Good -->
- Use `const` and `let` for variable declarations.
- Write functional React components.
- Use strict typing in TypeScript.
```
