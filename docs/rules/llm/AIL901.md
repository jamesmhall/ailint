# AIL901: llm-actionability-check

**Category**: [LLM](README.md)  
**Default Severity**: `Warning`

## Overview
Opt-in LLM-graded rule. The configured provider reads the file (with the
[actionability_system.md](../../../crates/ailint-llm/prompts/actionability_system.md)
prompt) and flags each directive that a competent agent could not execute
without asking the author what they meant.

Enable by adding an `llm:` block to `.ailint.yaml` (see the
[main README](../../../README.md)). Disable with:

```yaml
rules:
  disabled: [AIL901]
```

## Why it matters
Static rules like [AIL100](../semantic/AIL100.md) catch known vague phrases,
but they miss domain-specific hand-waving ("keep the pipeline healthy",
"prefer the standard flow"). An LLM reader has a much better chance of
noticing that a directive lacks the concrete thresholds, tools, or expected
outputs the agent needs.

## What it flags
Directives that are underspecified — e.g., missing:

- The exact command, tool, or artifact to produce.
- The threshold or measurable outcome.
- The conditions under which the rule applies.

## How to fix it
Follow the model's `fix_hint` verbatim, or rewrite the directive so that the
"how" and "when" are explicit. Prefer imperative bullets with concrete
commands or thresholds over hedged prose.

## Notes
- All findings are `warning` severity regardless of the LLM's rating.
- Cost is capped by the shared `llm.cost_cap_usd` setting.
