# AIL203 `tool-confirmation-required`

When an instructional prompt describes potentially destructive operations (e.g., dropping databases, deleting files, executing `rm -rf`), it is critical to explicitly require the agent to seek human approval before taking action.

## Why this is bad
Fully autonomous execution of irreversible or destructive actions without human-in-the-loop validation can cause data loss or system corruption.

## How to fix it
Include clear constraints demanding confirmation alongside the destructive action.

```markdown
<!-- Bad -->
When cleaning up the workspace, use `rm -rf` to remove old build artifacts.

<!-- Good -->
When cleaning up the workspace, ask for human permission before using `rm -rf` to remove old build artifacts.
```

## Configuration
Configurable via `.ailint.yaml` under the rule slug:

```yaml
rules:
  options:
    tool-confirmation-required:
      # Replace the built-in destructive-phrase list. Matched case-insensitively
      # as substrings of the document.
      destructive_phrases: ["rm -rf", "drop table"]
      # Add destructive phrases on top of the defaults.
      extra_destructive_phrases: ["gcloud projects delete", "kubectl delete ns"]
      # Replace the built-in confirmation-keyword list. If any of these appears
      # anywhere in the document, destructive-phrase hits are suppressed.
      confirmation_phrases: ["confirm", "approval"]
      # Add confirmation keywords on top of the defaults.
      extra_confirmation_phrases: ["require ticket approval"]
```
