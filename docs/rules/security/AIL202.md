# AIL202: no-sensitive-data-in-instructions

**Category**: [Security](README.md)  
**Default Severity**: `Error`

## Overview
Detects embedded secrets, SSH keys, UUID tokens, or static API keys in plaintext instruction files.

## Why it matters
Guidance files are usually checked into source control (e.g. `.github/copilot-instructions.md` or `.cursorrules`). Hardcoding tokens directly into text prompts creates a massive credential leak when pushed to GitHub.

## How to fix it
Tell the agent how to *resolve* the secret from its environment, rather than putting the secret in the markdown itself.

**Bad:**
> When querying Stripe, use the key `sk_test_1234567890`.

**Good:**
> When querying Stripe, read the `STRIPE_TEST_KEY` off the local ENV.

## Configuration
Configurable via `.ailint.yaml` under the rule slug:

```yaml
rules:
  options:
    no-sensitive-data-in-instructions:
      # Replace the built-in secret-shaped regex list.
      patterns: ['\bsk-[A-Za-z0-9]{20,}\b']
      # Add patterns on top of the defaults.
      extra_patterns: ['\bmyco_[A-Za-z0-9]{24,}\b']
      # Replace the built-in placeholder allowlist markers (substrings
      # within ±50 chars of a match are treated as documentation).
      allowlist_markers: ["EXAMPLE", "PLACEHOLDER"]
      # Add markers on top of the defaults.
      extra_allowlist_markers: ["FIXTURE_ONLY"]
```
